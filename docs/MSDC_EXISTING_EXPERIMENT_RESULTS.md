最能说明问题的是 `DJI_20250916100639_0001_V` 的 GT3：

这说明：

- 漏检根因首先在检测阶段：小 UAV/远距目标在默认高阈值下很少被检出。
- 低阈值检测提供了有效候选，但候选置信度和时序稳定性不足，导致 lifecycle 确认、保活和 ID 继承仍不够稳。
- ROI 重检在 GT3 上贡献很小，当前 ROI 策略更像“已知轨迹保活工具”，还不能解决长时间没有可靠轨迹种子的漏检。

## 4. 结论

1. 当前 MS-DC-ELT-lite 已经解决了两个早期可视化硬问题：空目标框和同目标重叠多框。在已保留结果中，`zero_area_count=0`、`duplicate_pairs_iou05=0`。

2. 对大目标 USV，跟踪稳定性基本可用。第二序列中的 GT1/GT2 在 60 秒结果里覆盖率达到 0.9983，且各自只对应 1 个输出 ID；第一序列两个 USV 的覆盖率也分别达到 0.9872 / 0.9166 到 0.9872 / 0.9333。

3. 小 UAV/远距目标仍是主要短板。`DJI_20250916100639_0001_V` 的 GT3 在 60 秒结果中高阈值覆盖只有 0.1615，低阈值覆盖提升到 0.6171，但最终输出覆盖只有 0.2637，并被 11 个 ID 分裂。这说明问题不是单纯 tracker 参数，而是“检测候选弱 + 时序确认不稳定 + ID 继承不足”的组合问题。

4. 低阈值检测方向是有效的，但还没有完全闭环。前 300 帧中 GT3 的 output 覆盖率达到 0.5967，明显高于 60 秒整体的 0.2637；但仍有多个 missing segments 和 3 个输出 ID，说明低阈值候选需要更强的稳定确认、保活和 lost 继承策略。

5. ROI 重检当前没有充分解决 GT3 漏检。GT3 的 `roi_low_det_coverage` 只有 0.0067 到 0.0076，说明 ROI 重检更多依赖已有轨迹位置；一旦目标长时间没有稳定轨迹种子，ROI 很难主动找回。

6. 海面/浪花误检仍需要处理。第一序列 `far_ratio` 在不同 run 中约 0.1181、0.2929、0.1241，说明仍有不少远离 GT 的输出框。后续应继续收紧低阈值候选的背景抑制、运动 clutter 过滤和类别/尺寸/位置先验。

7. 现有结果还不能证明 MS-DC-ELT 优于 BoT-SORT / OC-SORT baseline。当前保留下来的 TrackEval summary 只有 `Ours-full`，没有同一数据切片、同一导出设置下的 `botsort` / `ocsort` 对照表；因此只能说明 MS-DC-ELT 当前自身的行为、问题和修复方向，不能作为正式对比结论。

8. 下一轮正式评测需要补齐同一 run 下的 baseline 对照、完整 1 分钟或全帧 TrackEval summary、速度统计和分阶段耗时。当前最适合用作问题分析的 run 是 `20260605_165404` 的 4K 可视化视频和 JSONL，最适合引用指标的是 `20260604_201402` 与 `20260605_161308`。
